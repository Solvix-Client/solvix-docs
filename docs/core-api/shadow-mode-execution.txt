<h2 id="best-practices">Best Practices</h2>
<ol>
<li><strong>Don't shadow mutations</strong> — POST/PUT/DELETE on the secondary API creates real side effects</li>
<li><strong>Flag shadow requests</strong> — add a header so the secondary API can distinguish shadow traffic</li>
<li><strong>Compare responses AFTER both complete</strong> — don't block the primary on shadow results</li>
<li><strong>Log differences but don't alert</strong> — shadow comparison informs migration, it's not a production alert</li>
<li><strong>Use for gradual migration</strong> — shadow → compare → fix → switch</li>
</ol>
