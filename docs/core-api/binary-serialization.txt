<h2 id="how-it-works">How It Works</h2>
<p>When you set <code>bodyType: "protobuf"</code> or <code>bodyType: "msgpack"</code>, the request pipeline:</p>
<ol>
<li>Calls your <code>encoder</code> function with the request body</li>
<li>Sets the <code>Content-Type</code> header to the codec's <code>contentType</code></li>
<li>Sends the binary data as the request body</li>
</ol>
<p>When you set <code>responseType: "protobuf"</code> or <code>responseType: "msgpack"</code>:</p>
<ol>
<li>Reads the response as an <code>ArrayBuffer</code></li>
<li>Wraps it in a <code>Uint8Array</code></li>
<li>Calls your <code>decoder</code> function to parse it</li>
</ol>
<h2 id="error-handling">Error Handling</h2>
<p>If you use <code>bodyType: "protobuf"</code> without configuring <code>serialization.protobuf</code>, you'll get a clear error:</p>
<pre><code>Error: bodyType "protobuf" requires a serialization.protobuf encoder
</code></pre>
<h2 id="why-zero-dependencies">Why Zero Dependencies?</h2>
<p>Solvix does not bundle <code>protobufjs</code>, <code>@msgpack/msgpack</code>, or any other serialization library. This means:</p>
<ul>
<li><strong>No version conflicts</strong> with your existing dependencies</li>
<li><strong>Smaller bundle</strong> — only the codecs you use are included</li>
<li><strong>Flexibility</strong> — use any serialization library you prefer</li>
<li><strong>Custom formats</strong> — the <code>encoder</code>/<code>decoder</code> interface works for any binary format (BSON, CBOR, FlatBuffers, etc.)</li>
</ul>
