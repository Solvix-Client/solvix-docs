<h2 id="retry-and-error-interaction">Retry and Error Interaction</h2>
<p>When retries are enabled, the error is only thrown after all retries are exhausted:</p>

<p>Check <code>ctx.meta.retryCount</code> in error events to see how many retries were attempted.</p>
<h2 id="best-practices">Best Practices</h2>
<ol>
<li><strong>Use <code>SolvixBus</code> for global error monitoring</strong> — centralize error handling instead of try/catch on every request</li>
<li><strong>Set <code>onError</code> hooks</strong> for integrating with Sentry, Datadog, etc.</li>
<li><strong>Combine with <code>fallbackURLs</code></strong> — specify backup endpoints that are tried when the primary fails</li>
<li><strong><code>validateStatus</code> for non-standard APIs</strong> — some APIs return 200 with error bodies; handle them with <code>transformResponse</code></li>
<li><strong>Enable <code>devMode</code></strong> during development to get warnings about common misconfigurations</li>
</ol>
