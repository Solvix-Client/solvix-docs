1b:T1221,<p>Solvix was designed from the ground up with specific goals that shaped its architecture.</p>
<h2 id="1-zero-cost-abstraction">1. Zero-Cost Abstraction</h2>
<p>Features you don't use should cost nothing. A bare <code>createClient()</code> with no options should perform identically to native <code>fetch</code> — and it does.</p>
<p><strong>How:</strong> Every feature wraps a no-op when disabled. SHA-256 hashing for dedup keys is skipped entirely when <code>dedupe</code> and <code>cache</code> are both off. The priority queue defaults to <code>Infinity</code> concurrency, acting as a direct pass-through.</p>
<h2 id="2-typescript-first-not-typescript-only">2. TypeScript First, Not TypeScript Only</h2>
<p>The entire library is written in TypeScript with <code>strict: true</code>. But the public API is fully typed for consumers in both JS and TS — you get autocomplete either way.</p>
<p><strong>How:</strong> All option interfaces use generics. <code>client.get&#x3C;T>()</code> infers response types. <code>validateResponse</code> integrates with Zod/Valibot schemas without requiring them.</p>
<h2 id="3-resilience-by-composition">3. Resilience by Composition</h2>
<p>Individual resilience patterns (retry, circuit breaker, rate limiting) are well-understood. Solvix's innovation is making them compose correctly — retries respect rate limits, circuit breakers track retry failures, dedup is cache-aware.</p>
<p><strong>How:</strong> The pipeline architecture ensures stages execute in order. Downstream stages (like the circuit breaker) see the aggregated state from upstream stages (like retry attempts).</p>
<h2 id="4-transparent-observability">4. Transparent Observability</h2>
<p>You should never wonder "what happened" to a request. Timeline, profiling, correlation IDs, and structured logging are built into the core — not added as afterthoughts.</p>
<p><strong>How:</strong> The <code>SolvixContext</code> object that flows through every stage accumulates metadata. The final response always carries <code>meta.timeline</code>, <code>meta.profile</code>, and <code>meta.correlationId</code> if enabled.</p>
<h2 id="5-enterprise-security-by-default">5. Enterprise Security by Default</h2>
<p>The most common security issues in HTTP clients (CRLF injection, header smuggling, sensitive data in snapshots) are handled automatically. Additional layers are opt-in.</p>
<p><strong>How:</strong> Header sanitization runs on every request (strips <code>Host</code>, <code>Connection</code>, <code>Transfer-Encoding</code>). Snapshot mode automatically redacts sensitive headers.</p>
<h2 id="6-transport-agnosticism">6. Transport Agnosticism</h2>
<p>The HTTP transport should be swappable without changing application code. Whether you're using <code>fetch</code>, <code>undici</code>, <code>http2</code>, or a mock transport for testing, the API stays the same.</p>
<p><strong>How:</strong> The <code>SolvixTransport</code> type is a simple <code>(url, init) => Promise&#x3C;Response></code> signature. Proxy and TLS features use <code>undici</code> under the hood but expose the same API.</p>
<h2 id="7-minimum-dependencies">7. Minimum Dependencies</h2>
<p>Zero runtime dependencies (except optional <code>undici</code> for proxy/TLS). The entire library is self-contained, auditable, and easy to bundle.</p>
<p><strong>How:</strong> SHA-256 uses the Web Crypto API (built into all runtimes). Priority queue is hand-rolled (binary heap, not a library). No lodash, no <code>tslib</code>, no polyfills.</p>
<h2 id="8-universal-runtime-support">8. Universal Runtime Support</h2>
<p>The same API works in Node.js, browsers, Deno, Bun, and edge runtimes. No platform-specific code paths in the public API.</p>
<p><strong>How:</strong> Uses <code>fetch</code> which is available in all modern runtimes. Proxy/TLS features are isolated to a <code>node/</code> module and only imported when configured.</p>
<h2 id="non-goals">Non-Goals</h2>
<ul>
<li><strong>Not a replacement for WebSocket/SSE clients</strong> — Solvix handles HTTP requests. For persistent connections, use the appropriate client.</li>
<li><strong>Not a full OpenAPI client</strong> — Solvix doesn't generate code from OpenAPI specs. It's a runtime HTTP client.</li>
<li><strong>Not a GraphQL client</strong> — Solvix can send GraphQL requests but doesn't parse GraphQL schemas.</li>
</ul>
